Clinical RAG Safety Principled Abstention Evidence-Constrained Generation

Executive Summary

UQ-RAG is a safety-first RAG pipeline for clinical/medical QA. Unlike standard RAG baselines, it makes abstention principled, evidence-constrained, and structurally unbreakable. This document outlines the architecture, uncertainty quantification mechanisms, and key differentiators from both baselines and prior work on conformal prediction with LLMs.

UQ-RAG Architecture

The pipeline processes a user query through six sequential stages. Each stage is designed to enforce safety, verify evidence, and quantify uncertainty before any answer is presented to the user.

👤
1. User Query
Raw medical question entered by the user. No preprocessing or rewriting at this stage.
↓
🛡️
2. Pre-Generation Safety Gate
Deterministic regex-based classifier runs BEFORE any retrieval or LLM generation. Detects emergencies (chest pain, overdose, poisoning), prohibited queries (diagnosis, prescription), and patient-specific risk requests. If triggered, returns a fixed safety response immediately — no LLM involved.
↓
🔍
3. Corpus Retrieval
Pinecone vector search over the approved medical corpus. Returns top-k passages with metadata. Only approved, versioned documents are searchable. Every passage retains provenance, document hash, and page location.
↓
🧩
4. Claim Decomposition
LLM answer is decomposed into atomic claims. Each claim is a single, verifiable statement. This enables fine-grained verification rather than scoring the entire answer as a monolith.
↓
✅
5. Evidence Verification + Conformal Abstention
Bayesian log-odds fusion aggregates evidence across passages for each claim. Isotonic calibration maps raw probabilities to calibrated confidence. Conformal predictor (LAC) generates prediction sets with statistical coverage guarantees. If the conformal set does not contain SUPPORTED, the system abstains.
↓
📄
6. Cited Answer or Doubt Certificate
If claims are supported: compose answer with citation IDs. If claims are unsupported: emit a structured Doubt Certificate with abstention reason, conformal set, support probability, and human-review recommendation.

Uncertainty Quantification & Abstention Flow

UQ-RAG captures uncertainty at multiple levels and relates each to a specific abstention decision. This is not a single confidence score — it is a structured uncertainty budget.

🔢
Raw Probabilities
RandomForest outputs P(SUPPORTED), P(REFUTED), P(INSUFFICIENT) for each claim
→
📊
Calibrated Probabilities
Isotonic regression maps raw scores to calibrated confidence using held-out calibration set
→
🎯
Conformal Set
LAC method generates prediction set with guaranteed coverage (1-α). Set may contain multiple labels.
→
🚦
Abstention Decision
If SUPPORTED not in conformal set → abstain with Doubt Certificate. Else → present cited answer.

Key Insight: Uncertainty Causes Remain Separate

UQ-RAG represents query ambiguity, retrieval insufficiency, source conflict, and verifier uncertainty as separate causes. A single confidence number does not erase the cause of doubt. This is critical for clinical settings where the reason for abstention matters as much as the abstention itself.

MedRAG Baseline Architecture

MedRAG is a standard RAG pipeline with no explicit uncertainty quantification or abstention mechanism. It optimizes for answer completeness and fluency.

👤
1. User Query
Raw medical question entered by the user.
↓
🔍
2. Corpus Retrieval
Vector search over medical corpus. Returns top-k passages. No pre-generation safety check — retrieval happens first.
↓
🤖
3. LLM Generation
LLM generates answer using retrieved passages as context. Safety is implicit in LLM training — no deterministic gate.
↓
📄
4. Answer with Citations
Returns fluent answer with source citations. No abstention mechanism — will answer even when evidence is insufficient.

What Makes UQ-RAG Different — and Better for Clinical Settings

1. Evidence-Constrained Generation

Kumar et al. use LLM knowledge only. UQ-RAG restricts answers to an approved, versioned corpus. In clinical settings, this is the difference between "I don't know" and a plausible-sounding but unsupported claim.

2. Multi-Cause Uncertainty Representation

Kumar et al. treat uncertainty as a single scalar (LLM output probability). UQ-RAG separates query ambiguity, retrieval insufficiency, source conflict, and verifier uncertainty. This is critical for clinical QA where the reason for abstention matters as much as the abstention itself.

3. Structural Safety Guarantees

Kumar et al. have no safety mechanism. UQ-RAG's pre-generation safety gate is deterministic, pre-retrieval, and cannot be overridden by retrieved content. For clinical applications, this is not a "nice-to-have" — it is a regulatory requirement.

4. Principled Abstention with Traceable Reasons

Kumar et al. output an empty set when uncertain. UQ-RAG emits a Doubt Certificate with: abstention reason, conformal set, support probability, and human-review recommendation. This transforms "I don't know" from a failure into a traceable, auditable decision.

5. Claim-Level Verification

Kumar et al. verify the entire answer as a single unit. UQ-RAG decomposes answers into atomic claims and verifies each independently against retrieved evidence. This enables fine-grained abstention: "I can answer part A, but not part B" — impossible with monolithic verification.

The Melbourne Pitch

"Conformal prediction with LLMs, as Kumar et al. demonstrated, gives you coverage guarantees on answer sets. But for clinical RAG, coverage guarantees are not enough — you need evidence guarantees. UQ-RAG combines conformal abstention with strict evidence constraints, deterministic safety gates, and multi-cause uncertainty representation. We don't just say 'I don't know' — we say why we don't know, what evidence would be needed, and what the risk is of answering anyway. That's the difference between a coverage guarantee and a safety guarantee."
